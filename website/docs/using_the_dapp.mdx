# Quick-Start

The web interface at [https://testnet.tansu.dev](https://testnet.tansu.dev) is the easiest way to interact with Tansu. All contract calls use the [Stellar Wallets Kit](https://github.com/Creit-Tech/Stellar-Wallets-Kit) for non-custodial wallet integration.

> The steps below assume you are connected to **Testnet**. For Mainnet the flow is identical – only network selection and contract ID will differ.

## 1. Connect your wallet

1. Click **Connect** at the top-right corner.
2. Select your preferred wallet (Freighter, xBull, Albedo, a Ledger device, …).
3. Authorise the connection – your public key now appears in the header.
4. Click **Join** to register as a member – fill out details about yourself and, optionally, bind your Git identity by signing a message with your SSH key (see [Binding a Git identity](developers/membership.mdx#binding-a-git-identity)).

## 2. Register a project

1. Click **+ Add Project**.
2. Fill in:

- **Name** – 4 to 30 letters and digits, unique on-chain
- **Maintainers** – the Stellar addresses of the maintainers
- **Metadata** – The rest is metadata such as the link to the code repository.

3. Press **Register Project** and sign the transaction. Registration takes a non-refundable **5 XLM deposit**.

The dApp shows a **pending** status until the transaction is confirmed. Once done the new project appears on the dashboard.

## 3. Update your commit hash

On a project page, open **Code Finality**, click **Edit commit hash**, paste the full Git commit SHA and sign. The commit is stored on-chain and displayed alongside a link to the corresponding commit on the project's registered repository.

For an automated workflow, install the pre-push hook described in the [Git Hooks](developers/on_chain.mdx#git-hooks) section.

## 4. Attest a release

In **Code Finality**, maintainers can attach evidence to the commit (SBOM, CVE scan, attestation bundle) and **Attest** the commit or any evidence artifact. Once the share of maintainers set by the project's threshold has attested, the target is marked final. See [Code Finality](developers/code_finality.mdx).

## 5. Manage maintainers, badges & settings

- **Add badge** – maintainers can grant `Developer`, `Triage`, `Community`, `Verified` or `Default` badges to any member.
- **Update config** – change maintainers, metadata and the attestation finality threshold.

Badge weight is the default voting mode. Token-weighted proposals are chosen per proposal, and NQG contract weight applies to the SCF Public Goods project — see [Membership](developers/membership.mdx).

## 6. Create a proposal

1. Go to the **Proposals** page of a project.
2. Press **Submit Proposal** (shown to maintainers).
3. Fill in:

- **Title**
- **Description** – Markdown editor, optionally starting from a template (stored on IPFS)
- **Voting end** – calendar picker, at least a day and at most 30 days ahead
- **Voting mode** – public or anonymous, and optionally a token contract for token-weighted voting
- **Outcome Contracts** – optional contracts to invoke on each outcome (approved, rejected, cancelled), each with a target, function name and arguments. Templates pre-fill common cases, and the target can be a [Stellar Registry](https://stellar.rgstry.xyz) name instead of an address.

4. Submit and sign. Creating a proposal takes a **5 XLM deposit**, returned when the proposal is executed.

The proposal immediately appears with status **Active**.

## 7. Vote

While a proposal is **Active** press **Vote** and choose **Approve**, **Reject** or **Abstain**. The dApp automatically selects the correct call (public or anonymous) based on the proposal settings, and shows your voting power. Voting is free apart from network fees.

Maintainers can mark addresses as conflicted under **Conflict of Interest**, which prevents them from voting on that proposal, and can **Remove Vote** to drop an abusive vote.

## 8. Execute

After the voting window closes and the project's execution delay (24 hours by default) has passed, any maintainer can press **Execute Proposal**. If the proposal includes outcome contracts, the contract matching the result index is invoked (Approved = index 0, Rejected = index 1, Cancelled = index 2).
